## 1. Objective

The objective of this programme is to strengthen the computer science foundations, software engineering knowledge, and practical development capabilities of junior developers at OptiCore Solutions Ltd.

The developers are expected to develop the knowledge and skills necessary to independently design, develop, test, secure, deploy, and maintain production-grade software applications.

By the end of this programme, each developer should be able to:

- Understand fundamental computer science and programming concepts.
- Apply appropriate data structures, algorithms, and problem-solving techniques.
- Design and manage relational databases effectively.
- Develop maintainable frontend and backend applications.
- Understand application architecture and software design principles.
- Implement secure authentication, authorization, and data-handling mechanisms.
- Test, debug, and optimize applications.
- Deploy and maintain applications in production environments.
- Work independently on application modules while following professional software engineering practices.

| Week 2 | 10–12 | Databases, software engineering and system design |

**Expected approach:**

- Study and understand each topic.
- Practise implementing relevant concepts.
- Document areas of difficulty.
- Complete practical exercises.
- Prepare for the three-stage evaluation.

The one-month period is the target completion period, not an exemption from demonstrating competency.

## 5. Evaluation Process

Every topic will be evaluated through three consecutive stages.

**All three stages are mandatory. A developer must pass every stage to be considered competent in a topic.**

### Stage 1 — Understanding

**Objective:** Verify that the developer understands the concept and can explain it correctly.

Evaluation methods:

- Oral questioning
- Written questions
- Conceptual explanations
- Comparisons between related concepts
- Explaining advantages, disadvantages and use cases

Example:

Topic: Database Indexing

The developer should explain:
- What database indexing is.
- Why indexes are used.
- How indexes work at a basic level.
- Advantages and disadvantages of indexing.
- Situations where indexing is beneficial or unnecessary.

**Passing requirement:** Demonstrate a correct and sufficiently complete understanding without relying on memorized definitions alone.

### Stage 2 — Practical Application

**Objective:** Verify that the developer can independently apply the concept to solve a problem.

Evaluation methods:

- Coding exercises
- Practical assignments
- Database query exercises
- Application development tasks
- Debugging exercises
- Small implementation challenges

Example:

Topic: Database Indexing

The developer should:
- Identify a query that could benefit from indexing.
- Create an appropriate index.
- Execute and compare queries.
- Interpret the query execution plan.
- Explain the performance difference.

**Passing requirement:** Successfully demonstrate the ability to apply the concept independently.

### Stage 3 — Production-Level Understanding

**Objective:** Verify that the developer can use the concept correctly in a real-world production environment.

Evaluation methods:

- Realistic development scenarios
- Production-oriented assignments
- Code reviews
- Security and edge-case analysis
- Performance considerations
- Troubleshooting exercises
- Architectural decisions

Example:

Topic: Database Indexing

The developer should:
- Identify indexing opportunities in a real application.
- Consider query patterns and data volume.
- Understand the impact of indexes on INSERT, UPDATE and DELETE operations.
- Avoid unnecessary indexes.
- Consider index maintenance and production performance.
- Explain how they would diagnose a slow database query.

**Passing requirement:** Demonstrate sound engineering judgment and the ability to apply the concept reliably in a production context.

## 6. Passing Policy

The evaluation follows a strict progression.

| Stage | Requirement |
|---|---|
| Stage 1 | Understanding — Pass |
| Stage 2 | Practical Application — Pass |
| Stage 3 | Production-Level Understanding — Pass |

**All three stages must be passed.**

- Passing Stage 1 does not automatically qualify a developer for Stage 2.
- Passing Stage 2 does not automatically qualify a developer for Stage 3.
- Failure at any stage requires further study and reassessment.
- Developers may be reassessed after addressing their knowledge gaps.
- A topic is marked complete only after passing all three stages.

A high score in one subject cannot compensate for failure in another subject.

The final objective is to establish competency across the complete required curriculum.

## 7. Final Completion Criteria

A developer will be considered to have completed the programme when:

1. All 18 subjects have been covered.
2. All 521 topics have been studied.
3. Every topic has passed the Understanding evaluation.
4. Every topic has passed the Practical Application evaluation.
5. Every topic has passed the Production-Level Understanding evaluation.
6. Any identified weaknesses have been addressed and reassessed.
